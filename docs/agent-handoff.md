## 1. Контекст и архитектура проекта

**Livi Jewelry** — статически генерируемый интернет-магазин авторских украшений из натуральных камней и жемчуга (Алматы, Казахстан).
- **Сайт**: [livijewelry.kz](https://livijewelry.kz)
- **Стек**: Vanilla HTML5, CSS3, JavaScript (ES6+, без тяжелых фреймворков), Python 3 для сборки и синхронизации.
- **Локализация (3 языка)**:
  - Русский: корень (`/`, `/shop.html`, `/cart.html`, `/product/prod_XX.html`, 21 SEO-хаб)
  - Казахский: `/kz/` (`/kz/index.html`, `/kz/shop.html`, `/kz/cart.html`, `/kz/product/prod_XX.html`)
  - Узбекский: `/uz/` (`/uz/index.html`, `/uz/shop.html`, `/uz/cart.html`, `/uz/product/prod_XX.html`, сервисные страницы и SEO-хабы)
- **Каталог**: `products.json` — единый источник правды (70 товаров, 32 комплекта с вариативными ценами `bundle_options`, спецификации `specs`, микроразметка Schema.org).
- **Оформление заказа**: Корзина на стороне клиента + отправка структурированного заказа в WhatsApp / Google Apps Script Backend (`scripts/google_apps_script_order_backend.js`).
- **Интеграции и фиды**:
  - Google Merchant Center (`google_merchant_feed.xml`, `feed.xml`)
  - Kaspi.kz (`kaspi_feed.xml`, `feeds/kaspi_catalog.csv`)
  - 2ГИС (`2gis_feed.xml`, `feeds/2gis_catalog.csv`)
  - Pinterest (`pinterest_feed.xml`, `feeds/pinterest_bulk_pins.csv`)
  - Sitemap (`sitemap.xml` с Image Sitemap и xhtml:link hreflang на 3 языка)

#### 7. Микроразметка JSON-LD (Schema.org)
- **`Product` в каталогах (`shop.html`, `kz/shop.html`, хабы)** — **Критическая ошибка валидации Schema.org (P0)**:

    ```json
    {
      "@type": "ListItem",
      "position": 1,
      "item": {
        "@type": "Product",
        "name": "...",
        "image": "...",
        "offers": { "@type": "Offer", ... }
      }
    }
    ```

### 12.3. Мобильная вёрстка по `styles.css`

#### 1. Кнопки и интерактивные элементы меньше 44px (Touch Targets < 44×44px)
Согласно рекомендациям WCAG 2.1 (Success Criterion 2.5.5) и Apple HIG, минимальный размер области нажатия пальцем должен составлять не менее 44×44 CSS-пикселей.

- **`styles.css` (L980–990)** — `.remove-icon`: кнопка удаления позиции в корзине имеет размеры **28×28px**:
  ```css
  .remove-icon {
    width: 28px;
    height: 28px;
    font-size: 15px;
  }
  ```
  Пользователю на смартфоне крайне сложно попасть пальцем по 28-пиксельной кнопке без ложных нажатий по соседним элементам.
- **`styles.css` (L380–395, L1010–1025)** — Кнопки изменения количества товаров в корзине и карточках:
  * `.btn-qty`: `width: 30px; height: 30px;` (30×30px) ❌
  * `.qty button`: `width: 32px; height: 32px;` (32×32px) ❌
  * `.qty-btn`: `width: 36px; height: 36px;` (36×36px) ❌
- **`styles.css` (L450–465)** — Кнопка закрытия модального окна `.close`:
  * Задано `padding: 6px; font-size: 18px; line-height: 1;` → итоговая область нажатия составляет всего **30×30px**. На мобильном устройстве закрыть окно крестиком в правом верхнем углу затруднительно.
- **`styles.css` (L680–710)** — Чипы категорий и фильтров по камням (`.chip-link`, `.stone-chip`, `.hub-interlink-chips a`):
  * Задано `padding: 5px 12px !important;` при высоте шрифта 12px → суммарная высота чипа составляет **26–28px**.
- **`styles.css` (L1250–1270)** — Поля выбора `select` вне `.form-group`:
  * Задано `font-size: 13.5px;`. На iOS Safari любой клик по `<select>` или `<input>` с размером шрифта меньше 16px вызывает принудительный аппаратный зум экрана, сбивающий адаптивную сетку.

#### 2. Проблемы с горизонтальным скроллом (Overflow-X)
- **Отсутствие глобальной защиты на `html, body`**:
  * В `styles.css` для базовых селекторов `html` и `body` **не задано `overflow-x: hidden;`**.
  * Если любой вложенный элемент (например, заголовок с длинным неразрывным словом, таблица характеристик или абсолютный бейдж) выступает на 1–2px, вся страница на смартфонах начинает люфтить и раскачиваться по горизонтали.
- **Отсутствие изоляции скролла в чипсах**:
  * Горизонтальные скролл-бары категорий и камней (`.stone-chips`, `.filters`, `.category-pills`) имеют `overflow-x: auto;`, но не содержат свойства `overscroll-behavior-x: contain;`. На iOS при достижении конца горизонтального списка инерционный жест передается родительскому контейнеру страницы, вызывая нежелательный диагональный рывок.

#### 3. Проблемы с фиксированными и липкими элементами (`position: fixed / sticky`)
- **Плавающая кнопка WhatsApp (`.floating-wa`)**:
  * В `styles.css` задано:
    ```css
    .floating-wa {
      position: fixed;
      bottom: 24px;
      right: 24px;
      z-index: 99;
    }
    ```
  * **Отсутствуют безопасные отступы iOS**: нет `env(safe-area-inset-bottom)` и `env(safe-area-inset-right)`. На iPhone без физической кнопки «Домой» нижний отступ 24px попадает в 34-пиксельную зону системного Home Indicator. Пользователи при попытке свернуть браузер случайно кликают по WhatsApp, либо наоборот — не могут нажать кнопку из-за перехвата жеста системой.
- **Скролл-блидинг фона при открытом меню (`storefront-menu`) и модалках**:
  * При раскрытии шторки каталога скрипт `scripts/storefront-menu.js` вешает на `body` класс `.drawer-open`.
  * Однако в `styles.css` селектор `body.drawer-open` **только прячет плавающую кнопку WhatsApp** (`opacity: 0`), но **не блокирует прокрутку документа** (`overflow: hidden; touch-action: none;` отсутствует).
  * В результате при скролле открытого меню каталога на смартфонах одновременно прокручивается контент страницы под затемненной подложкой.
  * Аналогичная проблема наблюдается для модальных окон `body.modal-open`.
